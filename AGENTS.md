# Инструкции для AI-агентов и разработчиков

## Назначение проекта

Time Tracker — локальное tray-приложение для Windows. Актуальная реализация находится в `classic/`, написана на C# 5 и собирается системным компилятором .NET Framework в один `.exe`.

Основной пользовательский сценарий: 25 минут работы, решение «Пропустить» или «Отдыхать», короткий перерыв 5 минут и большой перерыв 90 минут после пяти завершённых рабочих интервалов.

## Технологические ограничения

1. Основной код совместим с C# 5 и компилятором `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.
2. Использовать только системные библиотеки .NET Framework: прежде всего `System`, `System.Drawing` и `System.Windows.Forms`.
3. Не добавлять WinUI, Windows App SDK, WPF, NuGet-пакеты, Generic Host, MVVM Toolkit или обязательную установку современного .NET.
4. Результат пользовательской сборки — один `.exe`; рядом могут создаваться только рабочие данные в `data/`.
5. Visual Studio не является обязательной частью сборки.
6. Не использовать синтаксис новее C# 5: file-scoped namespace, records, nullable annotations, interpolated strings, expression-bodied members, `init`, pattern matching и другие новые конструкции запрещены.
7. Основная целевая среда — Windows 10/11 x64.

Каталоги `src/`, проекты `.NET 10` и `TimeTracker.sln` относятся к предыдущему прототипу WinUI. Не развивать и не включать их в классическую сборку без отдельного запроса пользователя.

## Архитектура

Использовать Hexagonal Architecture / Ports & Adapters с направлением зависимостей внутрь:

```text
Presentation -> Application -> Domain
Infrastructure -> Application
```

- `classic/Domain/` содержит только правила, состояния и переходы таймера.
- `classic/Application/` содержит сценарии приложения, coordinator и порты.
- `classic/Infrastructure/` реализует часы, файловое хранение и интеграцию с Windows.
- `classic/Presentation/` содержит Windows Forms, tray icon и обработку UI-событий.
- `classic/Program.cs` является единственным composition root и вручную связывает зависимости.

Обязательные правила:

1. Бизнес-логика находится только в Domain/Application.
2. Domain не ссылается на Windows Forms, Drawing, файловую систему, реестр или реальные часы.
3. Время передаётся через `IClock`; таймер считается по deadline, а не по количеству UI-тиков.
4. `TimerSession` — источник истины; формы только показывают состояние и вызывают команды coordinator.
5. Один тип с самостоятельной ответственностью — один файл; имя файла совпадает с именем типа.
6. Не создавать универсальные `Utils`, `Helpers` и `Manager`.
7. Зависимости передавать через конструкторы. Service locator и глобальные изменяемые сервисы запрещены.
8. Windows API и формы не должны проникать во внутренние контракты.

## Правила таймера

- Обычная работа: 25 минут.
- Короткий перерыв: 5 минут.
- Большой перерыв: 90 минут после пяти завершённых рабочих интервалов.
- `Skip` начинает новую работу и не увеличивает и не сбрасывает счётчик.
- `Rest` начинает короткий перерыв.
- Пятый завершённый рабочий интервал переходит в ожидание решения, как и остальные; большой перерыв начинается только после команды `Rest`.
- `Skip` после пятого интервала сохраняет накопленный счётчик, поэтому следующий выбор `Rest` также запускает большой перерыв.
- После короткого или большого перерыва работа начинается автоматически.
- После запуска большого перерыва счётчик завершённых рабочих интервалов сбрасывается.
- Конфигурация `TEST_TIMER` использует 25, 5 и 90 секунд вместо минут, не меняя переходы состояний.
- Пауза и восстановление сессии не добавляются как неявные побочные эффекты.

## Tray и интерфейс

- После запуска приложение находится в системном трее и не открывает главное окно.
- Двойной щелчок по значку и пункт «Начать работу» запускают рабочий интервал.
- Контекстное меню содержит запуск, настройки и выход.
- Overlay является отдельной top-level формой высотой 64 px.
- Overlay занимает рабочую ширину только primary monitor.
- Во время работы overlay скрыт.
- После работы overlay красный и показывает «Пропустить»/«Отдыхать».
- Во время короткого и большого перерыва overlay зелёный.
- Overlay не должен блокировать остальную часть экрана.
- `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` применяется best effort; ошибка API не должна завершать приложение.
- Нельзя обещать полную невидимость при демонстрации экрана.

## Настройки и portable-режим

- Настройки хранятся в `data/settings.ini` рядом с EXE.
- Путь строится от `AppDomain.CurrentDomain.BaseDirectory`, а не от current working directory.
- Ошибка создания или записи `data/` должна сообщаться пользователю понятным сообщением с путём.
- Не хранить обычные настройки в `%AppData%`, `%ProgramData%` или каталоге установки Windows.
- Запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` допустима только для явно включённой пользователем автозагрузки.
- Не добавлять установщик, службу, backend, аккаунты, телеметрию или сбор активности без отдельного требования.

## Локализация

- Пользовательские строки должны поддерживать русский и английский языки.
- Для Windows Forms использовать `.resx`/встроенные `.resources`; не размножать пользовательские строки по form-классам.
- Новые ключи добавлять для обоих языков.
- Форматированные предложения хранить целиком, а не собирать из языковых фрагментов.
- Проверять подписи, tooltips, accessibility names и сообщения об ошибках на обоих языках.

Текущие строки, оставшиеся непосредственно в формах, считать техническим долгом и постепенно переносить в ресурсы без изменения поведения.

## TDD и тестирование

Новое поведение разрабатывать циклом Red -> Green -> Refactor:

1. Сначала добавить падающий тест в `tests/TimeTracker.Classic.Tests/`.
2. Запустить `./test-classic.ps1` и убедиться, что тест падает по ожидаемой причине.
3. Добавить минимальную реализацию.
4. Повторно запустить тесты.
5. Выполнить рефакторинг при зелёных тестах.

Тесты Domain/Application:

- не используют Windows Forms, реальное время и реальные задержки;
- используют fake/manual clock для временных сценариев;
- имеют имена, описывающие метод, сценарий и результат;
- проверяют deadline и все переходы таймера;
- собираются тем же C# 5 compiler через `test-classic.ps1`.

Обязательные сценарии:

- Start из Idle создаёт Work на 25 минут;
- работа не завершается до deadline;
- работа завершается при достижении или пропуске deadline;
- интервалы 1–4 переходят в ожидание решения;
- пятый интервал ожидает решения, а последующий Rest начинает LongBreak;
- Skip начинает Work без изменения счётчика;
- Rest начинает ShortBreak;
- окончание перерыва начинает Work;
- тестовые правила используют секунды.

Windows-интеграции проверяются вручную или отдельными integration-тестами: tray, primary monitor, автозагрузка, файловые пути и screen capture affinity.

## Рабочий процесс

Перед изменениями:

1. Прочитать этот файл и относящиеся к задаче исходники.
2. Выполнить `git status --short`.
3. Не перезаписывать несвязанные пользовательские изменения.

После изменений обязательно выполнить:

```powershell
.\test-classic.ps1
.\build-classic.ps1
.\build-classic.ps1 -Test
git diff --check
```

Проверить наличие результатов:

```text
artifacts/classic/TimeTracker.exe
artifacts/classic/TimeTracker-Test.exe
```

Для UI-изменений дополнительно вручную проверить tray, overlay, оба действия после работы, окно настроек и завершение приложения.

Не использовать `git reset --hard`, массовое удаление или перезапись пользовательских файлов без явного запроса.
