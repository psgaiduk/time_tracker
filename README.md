# Time Tracker

Time Tracker — небольшое Windows-приложение для чередования работы и отдыха. Оно запускается в системном трее и не требует установки современного .NET, WinUI, Windows App SDK или дополнительных библиотек.

Готовая сборка состоит из одного `.exe`. Приложение написано на C# 5 с использованием системных .NET Framework и Windows Forms.

## Как пользоваться

После запуска значок Time Tracker появляется в системном трее.

- Двойной щелчок по значку начинает рабочий интервал.
- Пункт «Начать работу» в контекстном меню делает то же самое.
- Пункт «Настройки» открывает параметры приложения.
- Пункт «Выход» полностью завершает приложение.
- Меню показывает текущий период, непрерывное время без отдыха и суммарное рабочее время за день.
- Значок в трее красный во время работы и показывает минуты непрерывной серии; во время отдыха он становится зелёным, в Idle — серым.

Обычный цикл таймера:

1. Работа — 25 минут.
2. После завершения работы появляется красная полоса.
3. «Пропустить» сразу начинает следующий рабочий интервал.
4. «Отдыхать» начинает короткий перерыв на 5 минут.
5. Во время перерыва полоса сначала полностью зелёная; по мере уменьшения оставшегося времени зелёная часть сокращается, открывая синюю основу.
6. После пяти рабочих интервалов появляется обычный выбор; кнопка «Отдыхать» запускает большой перерыв на 90 минут.
7. После окончания таймера перерыва зелёная полоса остаётся открытой; новый рабочий интервал начинается только после кнопки «Завершить отдых».
8. Кнопка «Завершить отдых» позволяет закончить короткий или большой перерыв раньше и сразу начать работу.

После появления красной полосы рабочее время продолжает считаться до выбора «Пропустить» или «Отдыхать». «Пропустить» начинает новый период без сброса времени непрерывной работы. «Отдыхать» завершает непрерывную рабочую серию.

Полоса показывается сверху только на основном мониторе. В настройках можно включить её отображение на всех виртуальных рабочих столах Windows. Закрепление и исключение из поддерживаемых способов захвата экрана выполняются best effort средствами Windows; это не защита от камеры или любого внешнего захвата.

## Настройки

В окне настроек доступны:

- попытка скрывать полосу при демонстрации экрана;
- отображение полосы на всех виртуальных рабочих столах Windows;
- запуск Time Tracker вместе с Windows.
- включение большого перерыва и выбор дней недели, когда он разрешён.
- промежуточный шаг «Заполни итоги работы» и необязательная ссылка для него.

Если большой перерыв выключен или текущий день недели не выбран, команда «Отдыхать» всегда запускает короткий перерыв на 5 минут. При включённой настройке в выбранный день после пяти рабочих периодов запускается большой перерыв.

Если шаг заполнения итогов включён, после нажатия «Отдыхать» сначала появляется синяя полоса. При заданной ссылке она выводится в той же строке после текста и остаётся кликабельной. Кнопка «Перейти к отдыху» закрывает этот шаг и запускает короткий или большой перерыв. При выключенной настройке отдых начинается сразу.

Настройки хранятся в `data/settings.ini`, а завершённые рабочие отрезки — в `data/history.csv` рядом с исполняемым файлом. История используется для подсчёта времени за текущий календарный день. Папка с программой должна быть доступна пользователю для записи.

## Требования

- Windows 10 или Windows 11 x64;
- системный .NET Framework 4.x;
- PowerShell — только для сборки проекта.

Visual Studio, NuGet и команда `dotnet` не требуются.

## Готовые варианты

Обычная версия использует минуты:

```text
artifacts/classic/TimeTracker.exe
```

Тестовая версия использует те же значения как секунды: работа 25 секунд, короткий перерыв 5 секунд, большой перерыв 90 секунд.

```text
artifacts/classic/TimeTracker-Test.exe
```

Для распространения достаточно передать соответствующий `.exe`. При первом запуске приложение самостоятельно создаст рядом папку `data`.

## Сборка

Открой PowerShell в корне репозитория.

Обычная сборка:

```powershell
.\build-classic.ps1
```

Тестовая сборка с секундами:

```powershell
.\build-classic.ps1 -Test
```

Сценарий вызывает системный компилятор напрямую:

```text
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe
```

Ему передаются все `.cs`-файлы из `classic/`, ссылки на стандартные `System.dll`, `System.Drawing.dll` и `System.Windows.Forms.dll`, а также `/target:winexe`.

## Тестирование

Запустить автоматические тесты классической реализации:

```powershell
.\test-classic.ps1
```

Сценарий собирает отдельный консольный test runner тем же системным `csc.exe`, запускает его и возвращает ненулевой код при ошибке.

Рекомендуемая полная проверка перед передачей EXE:

```powershell
.\test-classic.ps1
.\build-classic.ps1
.\build-classic.ps1 -Test
```

После этого вручную проверить:

- появление значка в трее;
- запуск рабочего интервала двойным щелчком;
- красную полосу после завершения работы;
- кнопки «Пропустить» и «Отдыхать»;
- зелёную полосу во время перерыва;
- сохранение настроек после перезапуска;
- расположение полосы на основном мониторе;
- запуск EXE из каталога с пробелами.

## Структура проекта

```text
classic/
  Program.cs                 точка входа и composition root
  Domain/                    состояния, правила и переходы таймера
  Application/               coordinator, часы и контракты настроек
  Infrastructure/            системные часы, INI и автозагрузка Windows
  Presentation/              tray, окно настроек и верхняя полоса

tests/TimeTracker.Classic.Tests/
  ClassicTimerTests.cs       автоматические тесты классического таймера

build-classic.ps1            сборка одного пользовательского EXE
test-classic.ps1             сборка и запуск тестов
artifacts/                   локальные результаты сборки
```

Направление зависимостей:

```text
Presentation -> Application -> Domain
Infrastructure -> Application
```

`Domain` не зависит от Windows Forms, реального времени, файловой системы или реестра. Интерфейс и Windows-операции находятся на внешних слоях.
